## v3.4.3 — 手画走锡不再被误判成短路

你贴的那 7 条错误，我一条条查过了：**它们都不成立**，是软件判定方式的问题，不是板子真的短了。

### 这 7 条错误到底是什么

三条信息其实在说同一件事：

```
底层边 8,23|8,24 被 MANUAL 与 $1N32 共用
网络间短路 @ 8,23：不同网络共用同一导电组 perfboard:8,23：MANUAL、$1N32
网络间短路 @ 8,24：不同网络共用同一导电组 perfboard:8,24：MANUAL、$1N32
```

`MANUAL` 是「手动走锡」这个占位名 —— 手画的线不属于任何网络，软件会看它压在哪些焊盘上，
自动认领那个网络的名称。问题出在**认领是按单条线算的**：

- 手画的一根线，软件是一段一段存的（一次拖动 = 一条记录）
- 碰到焊盘的那段 → 认领成 `$1N32`
- 没碰到焊盘的中间段 → 认领不到，留着 `MANUAL`
- 两段共用同一个孔 → 软件看到这个孔上同时有 `MANUAL` 和 `$1N32`，判定「两个网络抢同一个孔」

**同一根线，被当成了两根线互相短路。**

### 你自己的工程其实没有问题

我按连通关系把 80 条手画走锡归并成 20 组，逐组核对组内所有引脚的网络：

```
80 条手画走锡 → 55 条认领到了网络名，25 条没碰到焊盘而留 MANUAL
按连通组统计 → 每组只含 1 个网络
```

也就是说，这些线每一组都只连了一个网络，电气上完全正确。那 7 条错误一条都不成立。

### 改了什么

网络归属改成**按连通段传播**：

1. 碰到焊盘的段先定网络；
2. 没碰到焊盘的中间段，继承「与它共用一个孔的已定网络」，反复传播到稳定；
3. 仍定不下来的，整组只有一个网络就归入它（悬空铜箔跟着组走）；
4. 组里确实有多个网络，才保留 `MANUAL` —— 那才是真短路。

跳线也走同一套（原来跳线是逐条算的，同样会误判，`15,25 / 14,25` 那两条就是这么来的）。

### 验证

| 场景 | 结果 |
|---|---|
| 你的工程原样跑 DRC | 7 条 → **0 条** |
| 人为把 `C1.1($1N11)` 和 `C1.2(GND)` 用一条线短接 | **7 条**，全部指向 7,38 / 6,38 两个孔，含「物理铜连接了不同的期望网络：$1N11、GND」 |
| 还原工程再跑 | 0 条，26 元件 / 81 走锡 / 5 跳线原样 |

故意造的真短路仍然抓得到，而且只报真正短路的那两个孔，不会连带把整组几十个正常引脚一起报错。

自动化侧：`v34_features.js` 86 → 97 项（新增悬空段继承、三段链、无焊盘组、自带网络线、跳线五组场景），
16 套测试全绿，跑分 15476 零漂移。

### 注意

DRC 变干净不代表板子没问题的地方被掩盖了 —— 你自己画的那几段走锡里有 5 个网络（`$1N28 / $1N30 / $1N31 / $1N32 / $1N36`）
在 `failedNets` 里，飞线层仍会显示这些网络未布通，那部分该布线就布线。
