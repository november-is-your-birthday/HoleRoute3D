# v3.4.7 改板尺寸时键盘不再被板子抢走

## 问题

你想把板宽从 57 改成 28。删掉「7」的那一下，输入框里只剩「5」，板子当场缩成 5 列——
整块板重排、3D 场景重建，后面的「28」怎么都敲不进去。

## 根因

W / H 两个输入框是「每按一个键就写一次工程」的写法：

```js
onChange: K => S({ ...i, width: Jp(K.target.value) })
```

于是 `""`、`5`、`52` 每一个中间态都是一次**真实的板尺寸变更**：
不只是数字难看，它还会把板子缩小、重建场景、往撤销栈里塞好几条记录。
你正在打字，板子正在被重建，输入焦点自然守不住。

## 改法

把「显示」和「提交」拆开，抽成 `__lcBoardSizeField` 组件：

| 行为 | 说明 |
|---|---|
| 输入期间 | 只改本地草稿文本，工程值不动 |
| 提交时机 | **失焦 / 回车 / ↑↓ 步进**（↑↓ 仍是「按一次改一格」） |
| 聚焦 | **全选整个值**，点进去直接敲 `28` 就是替换 |
| `Esc` | 放弃本次编辑，回到工程当前值 |
| 空值 / 非数字 | 回退到工程当前值，不提交 |
| 越界 | 按 `[5,150]` 夹紧后提交（与原来的 `Jp()` 一致；面包板高度仍走 `M0()` 换算） |
| 外部改动 | 撤销、板四周的增删行列按钮 → 输入框自动跟随（正在编辑时不覆盖） |
| 同值提交 | 不写工程，避免污染撤销历史 |

聚焦全选这一条是配套的：如果不全选，你删掉「7」再敲「28」会拼成 `528`，
提交时被夹成上限 150 —— 还是改不成 28。

## 工具栏

- 删掉「飞线」右边那颗**「透视」按钮**。它紧贴走线相关按钮，很容易被当成布线功能误点。
- 「飞线」改名 **「飞线层」**，与代码里的既有叫法统一。
- 透视功能没有丢：右上角仍有透视图标，快捷键 `T` 照旧。

## 实测（打包后程序，CDP 真实鼠标点击 + 键盘输入）

```
初始 24×50
点 W 框（聚焦全选）→ 输入 28        输入框显示 28，板仍是 24×50   ← 中间态不再落盘
点板面空白失焦                      板变 28×50
点 H 框 → 输入 46（未提交）          板仍是 28×50
回车                                板变 28×46
工具栏                              … 清除DRC标记 ｜ 飞线层（13 → 12 个按钮，无「透视」）
```

`patches/tests/v347_ui.js` 用最小 hooks 模拟器直接渲染组件，25 项断言覆盖：
删到一半不提交、失焦提交一次、空值回退、上下限夹紧、同值不提交、↑↓ 步进、
`Esc` 放弃且 blur 不会把它偷偷提交、回车只提交一次、聚焦全选。

17 套测试全绿，`lint-lc --strict` 121 个函数，跑分 15476 零漂移。

## 怎么用

1. 点一下 W 或 H 输入框 —— 值会被整体选中；
2. 直接敲新的数字（例如 `28`），此时板子还不会动；
3. 按回车或点别处，板尺寸才生效；
4. 想微调一格，用 `↑` / `↓`；想撤销这次输入，按 `Esc`。
