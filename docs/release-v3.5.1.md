# v3.5.1 — 修正 Q1 三极管 B/E 标反（内测版）

> 这是 v3.5.0 的热修复。现有工程无需迁移，重新启动软件即生效。

## 修正内容

按你指出的实物位置，修正前三极管字母为：

```
x=8.02  B ｜ x=7.50  E ｜ x=6.98  C
```

正确应为：

```
x=8.02  E ｜ x=7.50  B ｜ x=6.98  C
```

C 的位置不变。

## 根因

问题不在字母的坐标，也不在脚号重编号，而是**封装判定过宽**。

该工程的 Q1 来自旧 Protel 网表，字段如下：

| 字段 | 值 |
|---|---|
| `kind` | `to92`（3D 实际使用的外形） |
| `value` | `S8050_SOT_NPN`（立创符号库 part 名） |
| `footprint` | 空 |
| `packageName` | 空 |

旧逻辑把 `value` 里出现的泛化 `SOT` 当成 SOT-23，套用了
`1=B 2=E 3=C`。但 `S8050_SOT_NPN` 只表示「SOT 类封装 + NPN」，
并没有写具体型号；模型和实物均是 TO-92，正确排布是 `1=E 2=B 3=C`。
因为只有前两脚互换，C 看起来一直是对的。

## 修复规则

判定优先级从高到低：

1. **网表提供真实引脚功能名** → 直接使用；
2. **用户手工选择脚序** → 严格按选择执行；
3. **明确的封装字段**（`footprint` / `packageName`）→ 按封装预设；
4. **没有明确封装** → 按当前 3D 外形，TO-92 使用 E-B-C；
5. 裸 `SOT` 不再猜测 SOT-23。

因此：

- 当前这个 TO-92 工程：`脚1 E ｜ 脚2 B ｜ 脚3 C`；
- 明确标注 `SOT-23` 的工程：仍是 `脚1 B ｜ 脚2 E ｜ 脚3 C`；
- 面板会明确显示「按 TO-92 常见排布 E-B-C 暂标，黄色」。
