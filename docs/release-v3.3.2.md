# 洞洞板布线 HoleRoute3D v3.3.2

> 洞洞板 / 万能板的 3D 元件摆放、反面走锡、跳线规划与 DRC 检查工具。
> 基于 [Tomjiang678/Perfboard-AutoRoute-3D-Windows](https://github.com/Tomjiang678/Perfboard-AutoRoute-3D-Windows) v2.0.0 二次开发，**非官方修改版**。

## 下载与安装（Windows x64，免安装）

1. 下载本页下方的 `ProtoRoute3D-v3.3.2-cn-win-x64.zip`（约 130 MB）；
2. **完整解压**到任意目录，例如 `D:\HoleRoute3D`；
3. 双击 `ProtoRoute 3D.exe`，不需要装 Python / Node / 任何运行时。

> 必须解压**整个目录**：程序依赖同目录的 `*.dll`、`*.pak`、`locales\`、`resources\`，只复制 exe 跑不起来。
> 首次运行可能提示「已保护你的电脑」，点「更多信息 → 仍要运行」即可（本版无代码签名）。

窗口标题显示 **ProtoRoute 3D v3.3.2** 表示版本正确。

## 本版重点：右键也认多选了

v3.3.1 修好了拖拽和 Ctrl 点选，但**右键菜单仍是单件操作**——选好一组元件，右键点「拔起」，
结果只有被右键的那一个动了。这一版把它接到同一套组合逻辑上。

### 问题在哪

右键的入口代码第一步就把选择集重写成了「当前点中的这一个」，之后所有操作自然只看到一个元件。
变换逻辑本身早就是按集合遍历的，所以这纯粹是入口丢信息，改了入口就通了。

### 现在的行为

| 场景 | 现在的行为 |
|---|---|
| 已选中 A、B，右键点 A | 选集保持 `[A,B]`，菜单里的拔起 / 放置 / 旋转 / 删除**对两个元件一起生效** |
| 已选中 A、B，右键点未选中的 C | 选集变为 `[C]`（与通用软件一致，避免误操作一整组） |
| 整组状态混合（部分在板上、部分已拔起） | 「放置」和「拔起」**都可用**，各自只处理需要变动的那些 |
| 整组都在板上 | 「拔起」可用，「放置」按灰（没有可放置的对象） |
| 整组都已拔起 | 「放置」可用，「拔起」按灰 |

菜单里「旋转 ±90°」沿用原规则：整组都在板上时不可用（引脚会离开原孔，建议先拔起再转）。

> 细节：右键后属性面板、状态栏会切到被右键的那个元件（主选中），但选集不丢——这样你既能整组操作，
> 也能顺手改单个元件的参数。

## 完整的多选操作速查

| 操作 | 按键 / 入口 |
|---|---|
| 加选 / 减选 | 按住 `Ctrl` 点击元件（`Ctrl` 点空白不再清空） |
| 整组移动 | 按住 `Shift` 拖动其中任意一个（无需先拔起） |
| 整组旋转 90° | 拔起后按 `空格`（顺时针）或 `R` |
| 整组拔起 / 放回 | `U` / `M`，或右键菜单 |
| 整组删除 | `Delete`，或右键菜单 |
| 全部拔起 | `Shift+U`，或工具栏「全部拔起」 |
| 撤销 / 重做 | `Ctrl+Z` / `Ctrl+Shift+Z` |

整组操作只记一步撤销，`Ctrl+Z` 一次全部回退。

## 验证（本版实测记录）

用浏览器级真实鼠标事件驱动打包后的程序复测：

- `Ctrl` 点 LED7 → `[LED7]`；再 `Ctrl` 点 R3 → `[LED7,R3]`；
- 右键 R3 → **选集仍为 2 个**，菜单显示 `放置(禁用) / 拔起 / 旋转+90°(禁用) / 旋转-90°(禁用) / 删除`；
- 点「拔起」→ **两个元件同时拔起**（修复前只有 R3 被拔起）；
- `Ctrl+Z` → 工程完全还原：23 元件 / 20 网络 / 77 走锡 / 5 跳线，全部回到「已在板上」。

自动化方面：15 套补丁回归全部 PASS（`multi_select.js` 由 34 项扩到 54 项），
布局布线跑分 15476 零漂移。
