# v3.4.13 — 支持嘉立创 .enet 网表（内测版）

> ⚠️ 仍是内测版，已知 / 未知缺陷都不少。重要工程请随时导出 JSON 备份。

## 新增：直接导入嘉立创 EDA 专业版的 `.enet`

立创「导出 → 网表」里有 6 种格式，本版支持其中信息量最大的 `.enet`（JSON）。

原来的 Protel2 `.net` **只有脚号**（`Q1-1` / `Q1-2` / `Q1-3`），三极管是 E 还是 B
全靠程序按封装去猜 —— 上一版把 SOT-23 猜反，根子就在这里。`.enet` 不一样：

```
MMBT5401（官方示例）
  pin 1  name=B   net=$13N32124
  pin 2  name=E   net=VCC5V0_USB_OTG
  pin 3  name=C   net=$13N32124
```

**引脚功能名直接写在网表里。** 你这份工程里能拿到的：

| 元件 | 从 `.enet` 得到 |
|---|---|
| LED1–LED10 | 脚1 = `C`、脚2 = `A`（阴极 / 阳极） |
| U1 (NE555) | `GND` `TRIG` `OUT` `RESET` `CONT` `THRES` `DISCH` `VCC` |
| U2 (4017) | `VSS` `CLOCK` `CLOCK/INHIBIT` `RESET` `VDD` `CARRY/OUT` … |
| SW1 | `A` / `B` |
| Q1 (S8050 SOT-23) | 仍是 `1/2/3` —— 这个符号没定义功能名 |

拿到真名的引脚，3D 上标的是**白色**（有确切依据）；拿不到才退回封装预设（暖黄）。

## 六种格式怎么选

| 格式 | 引脚功能名 | 封装名 | 本版 |
|---|---|---|---|
| **嘉立创EDA(专业版) `.enet`** | 部分有 | 标准名，含脚距 / 跨距 | ✅ 新增 |
| Protel2 `.net` | 只有脚号 | 自定义名 | ✅ 原有 |
| PADS `.asc` | 只有脚号 | decal 名 | ❌ 信息不增 |
| Allegro `.tel` | 只有脚号 | 只 decal 名 | ❌ 信息不增 |
| disa `.dnet` | 更少 | 部分 | ❌ |
| 仿真 `.dsnet` | SPICE 节点号 | 通常没有 | ❌ |

**结论：优先用 `.enet`，Protel2 保留作兼容。** 其余四种信息不比 Protel 多，
做出来也不会更准。

顺带一提 `.enet` 的封装名是这种形式：

```
SOT-23-3_L2.9-W1.3-P1.90-LS2.4-BR
              ↑脚距1.90  ↑跨距2.4
```

里面直接带脚距和跨距，洞洞板是 2.54 mm 栅格，这两个数值以后能拿来判断
「这个元件占几格」，比现在按类别估的 `leadSpacing` 精确。

## 怎么用

1. 立创 EDA 专业版 → 文件 → 导出 → 网表 → 网表类型选 **嘉立创EDA(专业版)(.enet)**
2. 软件里「工程 → 导入」把 `.enet` 拖进去（也可以点了选文件）
3. 点工具栏 **「生成元件 G」**
4. 需要的话再点「自动放置 P」

导入已有工程时，同名位号的元件会被**复用**，位置、布线都不动，
只更新引脚名 / 封装信息 —— 不会把你摆好的板子打乱。

## 实测结果

打包后程序，新建工程 → 导入你这份 `.enet` → 生成元件：

```
23 个元件、20 个网络

C1  C2   electrolytic_capacitor  2 脚  脚距1 跨距1
C3       radial_capacitor        2 脚  脚距1 跨距1
LED1-10  led                     2 脚  脚距1 跨距1
PR1      potentiometer           3 脚  脚距1 跨距1
Q1       to92                    3 脚  脚距1 跨距1
R1-R5    resistor                2 脚  脚距3 跨距1
SW1      tactile_switch          4 脚  脚距2 跨距2
U1 / U2  dip                     8 / 16 脚  跨距3

3D 标注：Q1 → B / E / C     LED1 → C / A
```

和 `v1.json`（早期用 Protel 网表导入的那份工程）逐项对照，
元件种类、脚数、脚距、跨距**全部一致**，说明两种格式走的是同一套判定。

## 边界处理

- **非数字脚号**（BGA 的 `1C12`）会按「数字原样、字母排后」重编号为 `1..n`，
  与 Protel 路径同一套规则；导入提示会告诉你有多少个被重编号。
- **`components` 是数组的 JSON** 认作工程文件，不会被当网表；
  反之 `.enet` 的 `components` 必须是对象。
- 版本不是 2.x 时给提示但仍尝试解析，不会直接拒绝。
- 缺 `Designator` 的条目跳过并提示；缺 `pinInfoMap` 的元件保留（按 2 脚占位）。
- 解析失败会明确说「嘉立创 .enet 网表解析失败：<原因>」，不再笼统说「无法识别格式」。

## 一个已知问题（与本版无关，但你可能踩到）

如果手动把工程 JSON 里的 `components` 清成空数组再打开，界面会白屏
（渲染时读了 `undefined.length`）。正常「新建工程」不会触发，
只有在文本编辑器里手工删元素时才会。要我修的话说一声。
