# v3.4.5 — 删列不再被「看不见的走锡」挡住

上一版加的四向增删行列，删除这一侧有个坑：**板上明明没有走锡，点 `－列` 还是提示
「还有走锡，先移开再删除」**。查下来是两个原因叠在一起。

## 原因一：一条画不出来的残片，占住了第 0 列和第 0 行

工程里有一条只有 1 个点的走锡记录（`points: [[0,0]]`，`locked: true`）。
它渲染不出任何东西，但在判断「这一列有没有东西」时被算成了占用，
于是**最左列和最上一行永远删不掉**，而且屏幕上完全看不出原因。

现在 `points.length < 2` 的记录一律不算占用，并在下一次改板尺寸时顺手清掉。

## 原因二：边界上有走锡就直接拒绝，其实没必要

孔被删掉之后，那段铜箔本来就不存在了。现在按内容分开处理：

| 边界上有什么 | 行为 |
|---|---|
| 元件 | **仍然拒绝**，并点名是哪几个（自动挪元件会改布局，得你自己决定） |
| 只有走锡 / 跳线 | 弹一句确认，写明会删几段；同意后连该列/行一起删 |
| 走锡 + 元件混着 | 按元件处理，先拒绝——不会因为「确认过」就偷偷删元件 |

## 顺带修一个误导

原来只有被拒时才弹提示，成功时一声不响。上一次的「还有走锡」会在屏幕上留 2.6 秒，
这时点另一条边，看到的就是上一次的文案——很像「这次又被拒了」。

现在成功与失败都会明确回一句：

```
已删除最右一列（现在 22 列），同时移除 3 段走锡，可 Ctrl+Z 撤销
最下一行还有 R3、SW1，先移开再删除
```

## 实测（打包后的程序，工程 23×45 / 81 段走锡 / 6 根跳线）

| 操作 | 结果 |
|---|---|
| 最左一列（原本被那条残片挡死） | 删除成功，23 → 22 列，走锡 81 → 80（残片被清掉） |
| 最右一列（3 段走锡） | 确认框「最右一列上还有 3 段走锡…继续？」→ 成功，走锡 80 → 77 |
| 最下一行（R3、SW1 在上面） | 仍然拒绝，提示点名 R3、SW1 |
| `Ctrl+Z` | 板宽 22 → 23、走锡 80 → 81，整步还原 |

自动化：`v34_features.js` 114 → 127 项（残片不挡、只有铜箔时删除、取消确认、
跳线随行删除、元件优先拒绝等 13 项），16 套测试全绿，`lint-lc --strict` 117 个函数，
跑分 15476 零漂移。
